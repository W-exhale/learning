### 预处理指令

#### 使用#ifndef和#endif

- 为什么要使用？
如果没有，编译器每次都会运行一遍所有头文件，耗时更长。
如果使用，编译器每次就运行修改了的头文件，节省时间。

这种用法的名称：
include guards, header guards

- 具体使用方法
```C
#ifndef MATH_OPERATIONS_H(这里是头文件的名字，要大写)

#endif // !MATH_OPERATIONS_H（写完上面那一行回车，可以自动补全，没有就自己加）
```
#### `#ifndef`和`#pragma once`的用法和区别

- 解释`#ifndef` 和 `#pragma once` 都是用于防止头文件内容重复编译的预处理器指令，但它们的工作方式和用途有所不同。
##### `#ifndef`的用法
1.   `#ifndef` 是一个宏定义指令，用于检查某个宏是否已经被定义。
2.   当你在一个头文件中遇到 `#ifndef` 指令时，编译器会检查后面的宏名是否已经定义。
3.  如果该宏尚未定义，编译器会继续编译 `#ifndef` 和 `#endif` 之间的所有代码，直到遇到 `#endif` 指令。
4.  如果该宏已经定义，编译器会忽略 `#ifndef` 和 `#endif` 之间的所有代码。
5.  `#ifndef` 通常与 `#define` 和 `#endif` 一起使用，以实现宏定义的条件编译。
6. 这个方式很繁琐，需要自己定义和检查宏
```C
  #ifndef MY_HEADER_FILE
  #define MY_HEADER_FILE
  
 // 头文件内容
  #endif // MY_HEADER_FILE
```

##### `#pragma once`的用法

1.   `#pragma once` 是一个编译器特定的指令，用于指示编译器只编译该文件一次，无论它被包含多少次。
2.  它不是宏，因此不需要与 `#define` 和 `#endif` 一起使用。
3.  `#pragma once` 的效果是全局的，它告诉编译器整个头文件只应该被编译一次，而不是每次包含时都编译。
4.  `#pragma once` 的行为在不同的编译器中可能会有所不同，但大多数现代编译器都支持它。
```
#pragma once

// 头文件内容
```
##### 区别
1. **语法和用途**：`#ifndef` 是用于条件编译的宏定义指令，而 `#pragma once` 是一个编译器指令，用于防止头文件内容重复编译。
2.   **兼容性**：`#pragma once` 可能不是所有编译器都支持，而 `#ifndef` 是标准的预处理器指令，几乎所有的编译器都支持。
3.  **可读性**：`#pragma once` 通常被认为更简洁，因为它不需要定义和检查宏。
4.  **灵活性**：`#ifndef` 可以与 `#define` 结合使用，实现更复杂的条件编译逻辑。

总的来说，`#pragma once` 是一个更现代、更简洁的解决方案，但 `#ifndef` 提供了更多的灵活性。如果可能，建议使用 `#pragma once`，因为它更易于理解和维护。

	if (arg1 > arg2) return 1;
