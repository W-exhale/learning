#### 分页
- Mybatis
	- 手写`limit`
	- 使用PageHelper插件
- Mybatis-Plus
	```java
	Page<User> page = new Page<>(1, 10);
	IPage<User> result = userMapper.selectPage(page, null);
	```

- 为什么要分页？
	- 为了避免一次性查询和返回大量数据带来的数据库压力、内存消耗和网络延迟问题，同时提升系统性能和用户体验，是列表查询接口的基本设计。
	- 假如一张用户表100万条记录不分页，而我写了`select * from user`
		- 数据库爆炸
			- 全表扫描、磁盘IO巨大、查询时间极长
		- 后端内存爆炸
			- 100万条记录、每条对象几十字节~几百字节、JVM瞬间拉满
		- 网络传输慢
			- 返回JSON几十MB、接口响应时间极长、前端等等等
		- 用户体验差
			- 页面加载很久、浏览器卡死、移动端崩
- 在*数据库层*完成分页


- 深度分页
	- 在数据量很大时，请求 靠后的页码（offset 很大）的分页查询
	- 例如mysql的`limit 99990, 10`
		- 不是直接跳到第99990条，而是从第一条开始扫描，读取前99990条后丢弃它们，再取后面10条。
		- 扫描了10万条，返回10条，如果加上排序等要求，更是卡上加卡
	- 危害
		- 查询越来越慢（随页数变慢）
		- 数据库CPU / IO飙升
		- 高并发下容易拖垮数据库
	- 解决方案
		- 限制最大页数（最多只允许翻到100页）
		- 使用基于索引的“游标分页”
			- 不用offset，使用上一页的最大id
			- 用于滚动加载
			```sql
			SELECT * FROM user
			WHERE id > 100000
			ORDER BY id
			LIMIT 10;
			```
		- 延迟关联
			- 思想：先在索引里“轻装上阵”快速定位，最后再回表取完整数据。
				```sql
				SELECT *
				FROM user
				JOIN (
				  SELECT id
				  FROM user
				  ORDER BY id
				  LIMIT 99990, 10
				) t ON user.id = t.id;
				```
			- 如上，将搜索分为内层和外层
				- 内层
					- 只查询id一列（id通常是主键有索引，数据库不用去磁盘找，直接在体积很小的索引树（B+ Tree）上就能完成扫描
					- `SELECT id FROM user ORDER BY id LIMIT 99990, 10`
				- 外层关联
					- `JOIN (...) t ON user.id = t.id`
					- 通过主键直接定位（Point Lookup）
### 其他功能
#### 自动填充
- 是什么
	- MyBatis-Plus 提供的一种机制，在插入或更新数据时，自动为实体对象填充如创建时间、更新时间等公共字段，减少重复代码并保证数据一致性。

```java
@TableField(fill = FieldFill.INSERT)
private LocalDateTime createTime;
```

- 几乎每张表都有下面字段
	- `create_time、update_time、created_by、updated_by、deleted`
	- 如果不自动填充，每次都需要写
		```java
		user.setCreateTime(LocalDateTime.now());
		user.setUpdateTime(LocalDateTime.now());
		```
- MP会自动填`createTime、updateTime`

- 使用方式
	1. 实体类标注字段
		```java
		@TableField(fill = FieldFill.INSERT)
		private LocalDateTime createTime;
		
		@TableField(fill = FieldFill.INSERT_UPDATE)
		private LocalDateTime updateTime;
		```
	2. 编写填充处理器
		1. 统一入口，统一规则
		2. 需要实现MyMetaObjectHandler接口
			```java
			@Component
			public class MyMetaObjectHandler implements MetaObjectHandler {
			
			    @Override
			    public void insertFill(MetaObject metaObject) {
			        this.strictInsertFill(metaObject, "createTime",
			                LocalDateTime.class, LocalDateTime.now());
			        this.strictInsertFill(metaObject, "updateTime",
			                LocalDateTime.class, LocalDateTime.now());
			    }
			
			    @Override
			    public void updateFill(MetaObject metaObject) {
			        this.strictUpdateFill(metaObject, "updateTime",
			                LocalDateTime.class, LocalDateTime.now());
			    }
			}
			```

- SQL执行前由MP拦截并注入字段值，注意自动填充不是数据库默认值
- 自动填充不会覆盖手动set的值
- XML自写SQL默认不走自动填充

#### 逻辑删除
- 是什么
	- 不真正从数据库删除，只标记字段“已删除”
```java
@TableLogic
private Integer deleted;
```

- 实现方式
	- 表中添加一个deleted字段，用0和1表示是否删除
- MP作用
	- 自动改SQL
	- deleteById(id)：`UPDATE user SET deleted = 1 WHERE id = ?`
	- selectById(id)：`SELECT * FROM user WHERE id = ? AND deleted = 0`
	- 自动拼接`deleted = 0`，即自动在sql语句后加上`where deleted = 0`
	- 自动将delete变成update
	- 自动忽略已删除数据

- 和自动填充一起用，实现插入时默认`deleted = 0`的功能
	```java
	@TableLogic
	@TableField(fill = FieldFill.INSERT)
	private Integer deleted;
	
	this.strictInsertFill(metaObject, "deleted", Integer.class, 0);
	
	```

- 对xml的sql无效
- 不用逻辑删除的情况
	- 日志表（只增不删）
	- 中间表（强一致性）
	- 数据量极大且无恢复需求

#### 乐观锁
- 一种并发控制机制，用“版本号校验”来防止多个人同时修改同一条数据时发生数据覆盖。

```java
@Version
private Integer version;
```

- 举例
	- 假如A和B同时买库存量为10的S，那么两人买完后库存量本应该是8，但由于是同时买。A要求10-1库存量改为9，B也要求10-1覆盖库存量=9，最终库存量 = 9。

- 思想：假设冲突不常发生，但在更新时检查“有没有别人改过”
	- 方式：使用版本号
	-

### 定制SQL
- 简单SQL
```java
@Select("select * from user where age > #{age}")
List<User> selectByAge(int age);
```

- 复杂SQL使用xml
	- xml一般放在spring项目的resource目录下（创一个mapper文件夹），路径要和Mapper接口对应
	- 在配置文件中添加默认扫描路径
		```yaml
		mybatis:
		  mapper-locations: classpath:mapper/*.xml
		```
	- namespace一致
		- xml文件
			```xml
			<mapper namespace="com.example.project.mapper.UserMapper">
			```
		- java文件
			```java
			package com.example.project.mapper;
			public interface UserMapper { }
			```
	- 方法名一致
		```java
		User selectById(Long id);
		```
		```xml
		<select id="selectById" resultType="User">
		    select * from user where id = #{id}
		</select>
		```
