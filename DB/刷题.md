## 178.分数排名
![Pasted image 20241121083903](images/Pasted%20image%2020241121083903.png)

- 要求：
编写一个解决方案来查询分数的排名。排名按以下规则计算:
- 分数应按从高到低排列。
- 如果两个分数相等，那么两个分数的排名应该相同。
- 在排名相同的分数后，排名数应该是下一个连续的整数。换句话说，排名之间不应该有空缺的数字。
按 `score` 降序返回结果表。

![Pasted image 20241121083955](images/Pasted%20image%2020241121083955.png)

1. 使用dense_rank()窗口函数
```sql
SELECT S.score, 
DENSE_RANK() OVER (
ORDER BY S.score DESC 
) AS 'rank' 
FROM Scores S; 
```

mysql8才有的函数
`dense_rank()`：返回当前行在其分区中的排名，没有间隙。对等项被视为并列并获得相同的排名。

2. 相关子查询
```sql
select S1.score,(
	select count(distinct S2.score)
	from Scores S2
	where S2.score >= S1.score
)as 'rank'
from Scores S1
order by S1.score desc;
```

通过去重的表来获取每行的排名

3. 使用内连接，和方法2的思想差不多
```sql
select S.score,count(distinct T.score) as 'rank'
from Scores S inner join Scores T on S.score <= T.score
group by S.id,S.score
order by S.score desc;
```

## 180.连续出现的数字
![Pasted image 20241121092705](images/Pasted%20image%2020241121092705.png)

- 要求
找出所有至少连续出现三次的数字。
返回的结果表中的数据可以按 **任意顺序** 排列。

1. 使用子查询
```sql
select distinct num as ConsecutiveNums
from Logs
where (id + 1, Num) in (select * from Logs)
and (id + 2, Num) in (select * from Logs)
```

2. 使用连接（数据多了效率就会很低），思想和上面的差不多
```sql
select distinct l1.num as ConsecutiveNums
from Logs l1, Logs l2,Logs l3
where l1.id = l2.id - 1
and l2.id = l3.id - 1
and l1.num = l2.num
and l2.num = l3.num
```

## 185. 部门工资前三高的所有员工
- 表结构![Pasted image 20241126152626](images/Pasted%20image%2020241126152626.png)
- 要求：公司的主管们感兴趣的是公司每个部门中谁赚的钱最多。一个部门的 **高收入者** 是指一个员工的工资在该部门的 **不同** 工资中 **排名前三** 。
	编写解决方案，找出每个部门中**收入高的员工** 。
	以 **任意顺序** 返回结果表。

![Pasted image 20241126152804](images/Pasted%20image%2020241126152804.png)

- 解决方案
使用连接
```sql
select Department.name as 'Department',
Emp1.name as 'Employee',
Emp1.salary as 'Salary'
from Employee Emp1 inner join Department on Department.id = Emp1.departmentId
where (select count(distinct Emp2.salary) 
	   from Employee as Emp2 
	   where Emp1.departmentId = Emp2.departmentId and Emp2.salary > Emp1.salary) < 3
```

- 使用窗口函数
```sql
select d.name as Department, 
e.name as Employee, 
e.salary as Salary 
from ( select *, 
	  dense_rank()over(partition by departmentId order by salary desc) as erank 
	  from Employee ) as e 
left join Department d on d.id = e.departmentId 
where erank <= 3
```

`dense_rank()over(partition by departmentId order by salary desc) #根据部门id分组，再对组内按照薪水从大到小排序，并生成对应的排名编号`

## 262.行程和用户
![Pasted image 20241128154425](images/Pasted%20image%2020241128154425.png)

- 要求
**取消率** 的计算方式如下：(被司机或乘客取消的非禁止用户生成的订单数量) / (非禁止用户生成的订单总数)。
编写解决方案找出 `"2013-10-01"` 至 `"2013-10-03"` 期间非禁止用户（**乘客和司机都必须未被禁止**）的取消率。非禁止用户即 banned 为 No 的用户，禁止用户即 banned 为 Yes 的用户。其中取消率 `Cancellation Rate` 需要四舍五入保留 **两位小数** 。
返回结果表中的数据 **无顺序要求** 。

- 事例
![Pasted image 20241128154511](images/Pasted%20image%2020241128154511.png)
![Pasted image 20241128154546](images/Pasted%20image%2020241128154546.png)

- 解决方案1：
```sql
SELECT 
    T.request_at AS `Day`, 
    ROUND(
        SUM(
            IF(T.STATUS <> 'completed', 1, 0)  -- 如果状态不是"completed"，就计为1（即取消）
        ) / COUNT(T.STATUS), 
        2  -- 保留2位小数
    ) AS `Cancellation Rate`
FROM Trips AS T
JOIN Users AS U1 ON (T.client_id = U1.users_id AND U1.banned = 'No')  -- 确保用户没有被禁用
JOIN Users AS U2 ON (T.driver_id = U2.users_id AND U2.banned = 'No')  -- 确保司机没有被禁用
WHERE T.request_at BETWEEN '2013-10-01' AND '2013-10-03'
GROUP BY T.request_at
HAVING COUNT(T.STATUS) > 0;  -- 确保不会除以零（即没有订单的天数不计算）
```
- 思路
1. 连接时将禁用的用户和司机筛选走
	1. 注意用户和司机需要分开筛选
	2. `if (client_id = users_id 或 driver_id = users_id) 且 users_id没有被禁止{此条记录没有被禁止}`，思考：这个其实是错误的
2. 控制日期范围
3. 确保天数不为0
4. 进行计算
	1. if和sum结合使用，用1表示未取消的
	2. 总数使用count计算经过上面筛选后的总订单数

- 解决方案2
```sql
SELECT 
	T.request_at AS `Day`, 
	ROUND( 
		SUM( 
			IF(T.STATUS = 'completed',0,1) 
		) / COUNT(T.STATUS), 
		2 
	) AS `Cancellation Rate` 
	FROM trips AS T 
	WHERE T.Client_Id NOT IN ( 
		SELECT users_id 
		FROM users 
		WHERE banned = 'Yes' 
	) AND T.Driver_Id NOT IN ( 
		SELECT users_id 
		FROM users 
		WHERE banned = 'Yes' ) 
	AND T.request_at 
	BETWEEN '2013-10-01' AND '2013-10-03' 
	GROUP BY T.request_at 
```

与方案1的不同是，筛选禁止用户和司机的方式，这里的筛选是通过in来实现的而不是连接
