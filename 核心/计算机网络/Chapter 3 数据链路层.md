### 2. 组帧
- 即封装成帧
#### 主要问题
- 帧定界
	- 如何让接收方能够确定帧的界限
		- 如何分辨帧和帧之间的边界
- 透明传输
	- 接收方链路层需要能从收到的帧内恢复原始SDU（去除帧定界的附加信息，恢复原貌），让网络层感受不到将分组封装成帧的过程
#### 四种组帧方法
- 字符计数法
	- 每个帧的开头用一个定长计数字段表示帧长
		- 帧长=计数字段长度+帧的数据部分长度
	- 缺点
		- 任何一个计数字段出错，都会导致后续所有帧无法定界
	- ![[Pasted image 20251227144944.png]]
- 字节填充法
	- Escape Character
	- Start of Header
	- End of Transmission
	- ![[Pasted image 20251227145332.png]]
	- 发送方在特殊字符前填充转义字符ESC，接收方删除ESC

- 零比特填充法（常用）
	- 解决与控制字符冲突的不同方法
		- 数据部分遇到连续5个1就填充一个0
		- 接收方在数据部分遇到五个1就删掉后面的0
	- HDLC、PPP
	- ![[Pasted image 20251227145827.png]]

- 违规编码法（常用）
	- 利用*曼彻斯特编码*中间一定会跳变的特性
		- 如果没有跳变则“违规”，表示开始和结束
	- 数据原样给到物理层
		- 需要物理层配合在开始和结束插入一个时钟周期的违规信号
	- ![[Pasted image 20251227150152.png]]

### 1. 检错编码
#### 奇偶校验码
- 原理
	- 奇校验码
		- 整个校验码1的个数为奇数（包括校验位）
	- 偶校验码
		- 整个校验码1的个数为偶数
	- ![[Pasted image 20251227151011.png]]
- 检错方式
	- 偶校验更常用
		- 可以用异或门（模2加）来实现
			- 全部加起来除以2得到的余数就是偶校验位的数
		- 接收方验证时将所有数相加应=0，若为1即出错
		- 缺点
			- 无法检测偶数次错误
	- ![[Pasted image 20251227151450.png]]
#### CRC校验码
- 循环冗余校验，Cyclic Redundancy Check
- 基本思想
	- 发送方和接收方约定一个“除数”
		- 对比将数据除以这个除数后得到的余数
	- 被除数
		- K个信息位+R个校验位
		- 保证除法余数=0

- 如何构造
	- 通过生成多项式的方式得到除数
		- 假设生成多项式为：$G(x)=x^3+x^2+1$
		- $G(x)=1*x^3+1*x^2+0*x+1*x^0$
		- 除数=1101
	- R=生成多项式的最高次幂，3
		- 将信息码左移3位，低位补零
	- 对移位后的信息码进行模2除法，产生余数，得到校验位
		- 模2除（+模2减，效果和模2加一样，就是异或）
			- 取商只看最高位，如果是1就上1
			- ![[Pasted image 20251227152833.png]]
	- 得到的CRC码
		- 信息码+001

- 如何检错
	- 接收方将接收到的信息用1101进行模2除
		- 余数若为000，则未出错
		- 校验位为3位，只有后面8位出错才能找到对应的错误
			- 如果是8位再往前余数会重新从001开始
- 如何纠错
	- 如果校验位能覆盖所有信息位+校验位，则可以进行纠错
	- $2^R>=K+R+1$
	- 很少用，需要的校验位太多
	- 只能检测单比特错误

- 检错能力
	- 检测所有奇数个错误
	- 所有双比特的错误
	- 所有小于校验位长度的连续错误

### 2. 纠错编码
- 基本思想
	- 将信息位分组进行偶校验，可以得到多个校验位
		- 该多位校验位可直接标注出错位置
	- k位校验位可以表示$2^k$种状态，信息位n位
		- n+k位中任何一位都可能出错
		- 所以，$2^k>=n+k+1$
		- 速记
			- ![[Pasted image 20251227154708.png]]

- 求解步骤
	1. 确定海明码位数
		- 设置信息位$D_4D_3D_2D_1$，则校验位$P_3P_2P_1$
		- 规定
			- 校验位$P_i$必须在海明码$2^{i-1}$位置
			- ![[Pasted image 20251227155115.png]]
	2. 求校验位的值
		- 将信息位进行分组
			- ![[Pasted image 20251227155606.png]]
			- ![[Pasted image 20251227155650.png]]
	3. 检错纠错
		- 用相同方式进行分组
		- ![[Pasted image 20251227155940.png]]
- 检错能力
	- 检错：2位
		- 上面的方法无法确定是1位还是两位发送错误
		- 所以可以给整个海明码加上一个全校验位（对整体进行偶校验）
			- 如果000且全校验位无错，则无错误
			- 如果非000且全校验位有，则1位错
			- 如果非000且全无错，则2位错，需重传
	- 纠错：1位

### 1. 滑动窗口机制及其他机制
- 发送窗口$W_T$
	- transmit
	- 在发送窗口内的帧才能被允许发送
- 接收窗口$W_R$
	- receive
	- 在接收窗口内的帧才能接收
- ![[Pasted image 20251229092740.png]]

- 确认机制
	- 确认帧ACK_i
		- 若接收方收到i号帧，且未检测出差错，需要发送方返回确认帧ACK_i
	- 否认帧NAK_i
		- 若接收方收到i号帧，但有差错，需要丢弃，则给发送方返回否认帧NAK_i

- 重传机制
	- 超时重传
		- 发送方超时未收到ACK_i，则重传i号帧
	- 请求重传
		- 若发送方收到NAK_i，则重传

- 帧编号
	- 至少需要用n bit给帧编号
	- 要求
		- $W_T+W_R\leq 2^n$

		- 例子
			- ![[Pasted image 20251229142118.png]]

### 1. 信道划分
#### 时分复用（TDM）、统计时分复用（STDM）
- 多个节点共享同一个信道，如果同时发送声音信号，会相互干扰
- 时分复用
	- Time Division Multiplexing，TDM
	- 解释
		- 将事件分为等长的“TDM帧”，每个“TDM帧”又分为等长的m个“时隙”，将m个时隙分配给m对用户（节点使用）
	- 缺点
		- 每个节点最多只能分配到信道总带宽的$\frac{1}{m}$
		- 如果某节点暂时不发送数据，会导致被分配的“时隙”闲置，信道利用率↓
	- ![[Pasted image 20251229142923.png]]

- 统计时分复用
	- Statistic Time Division Multiplexing，STDM
		- 异步时分复用
	- 解释
		- 在TDM的基础上，动态按序分配时隙
	- 优点
		- 如果有需要，一个节点可以在一段时间内获得所有信道带宽资源
		- 如果某节点暂不发送数据，可以不分配“时隙”，信道利用率更高
	- ![[Pasted image 20251229143205.png]]

#### 频分复用（FDM）、波分复用（WDM）
- 如果两个信号频率很接近，就很难分辨
	- 将信道频率进行拆分，用不同的频率范围发送信号
	- ![[Pasted image 20251229143539.png|200]]
- 频分复用
	- Frequency Division Multiplexing，FDM
	- 解释
		- 将信道的总频带划分为多个子频带，每个子频带作为一个子信道，每对用户使用一个子信道进行通信
	- ![[Pasted image 20251229143809.png]]
	- 优点
		- 各节点可同时发送信号，充分利用了信道带宽
	- 缺点
		- FDM技术只能用于模拟信号传输

- 波分复用
	- Wavelength Division Multiplexing，WDM
	- 光的频分复用
	- ![[Pasted image 20251229144111.png]]
	- 利用了光信号频带范围大的特点，本质上还是频分复用
#### 码分复用（CDM）
- 2G、3G时代，节点之间通信使用CDMA（Code Division Multiple Access）技术
	- CDMA底层原理就是码分复用（CDM）
- 解决问题
	- 两个节点同时发送信号，CDM允许信号相互干扰、叠加。
	- 接收方有办法将来自各节点的信号分离

1. 给各个节点分配专属“码片序列”
	- 码片序列包含m个码片（信号值），可看作“m维向量”
		- m维向量的分量通常取1或者-1
	- 要求
		- 各节点的“m维向量”必须相互正交
	- 相互通信的各节点知道彼此的码片序列
2. 发送方如何发送数据
	- 节点发出m个信号值与“码片序列”相同，表示比特1
	- 节点发出m个信号值与“码片序列”相同，表示比特1
	- ![[Pasted image 20251229150108.png]]
3. 信号在传输过程中“叠加”
	- 当多个发送方同时发送数据时，信号值会叠加
		- 本质是多个m维向量的加法
		- ![[Pasted image 20251229150539.png]]
4. 接收方接收数据
	- 接收方收到的是叠加信号，需要从中分离出发送方的数据
	- 叠加信号与发送方的码片序列进行规格化内积
		- 1-->1
		- -1-->0
		- ![[Pasted image 20251229151423.png]]

#### CSMA/CD协议
- CSMA/Collision Detection（冲突检测）
	- 检测到冲突立即停发
- 用于早期的*有线以太网*
	- 用同轴电缆连接多个节点组成有线局域网
	- 用集线器连接多个节点组成有线局域网
- 机制
	- 先听后发，边听边发，冲突停发，随机重发
	- 随机重发
		- 截断二进制指数退避算法
			- 随机等待一段时间=r倍争用期，其中r是随机数
				- 争用期是一段固定大小的时间
			- 如果$k\leq 10$，在$[0,(2^k-1)]$区间随机取一个整数r
			- 如果如果$k> 10$，在$[0,(2^{10}-1)]$区间随机取一个整数r
	- 注
		- 第10次冲突是随机重发的分水岭
		- 第16次冲突直接放弃传帧，报告上级（网络层）
- ![[Pasted image 20251229155045.png]]
- 争用期
	- =2×最远单向传播时延（考虑距离最远的两个节点）
	- 如果争用期内为检测到冲突，则本次帧发送不会发送冲突
	- CSMA/CD没有ACK机制，所以无冲突=发送成功
	- ![[Pasted image 20251229155725.png]]
- 最短帧长
	- =2×最大单向传播时延×信道带宽
	- 若收到的帧小于最短帧长，视为无效帧
	- 如果实际发送的数据很少，可以填充至合法长度后发送
- 接收方

#### CSMA/CA协议
- CSMA/Collision Avoidance 冲突避免
	- 不检测冲突，发送前尽量避免冲突
- 用于IEEE 802.11无线局域网（WIFI）
- 家用路由器
	- ![[Pasted image 20251229160915.png]]
	- 校园网
		- ![[Pasted image 20251229161010.png]]
- 假如使用CSMA/CD
	- ![[Pasted image 20251229161334.png]]
- 机制
	- 发送方
		- 先听后发，忙则退避
		- 若信道空闲，间隔DIFS后，再发送帧（一次性发完，不用检测冲突）
		- 不空闲则随机退避
	- 随机退避
		- 用二进制指数退避算法确定一段随机退避时间（倒计时）
		- 发送方会保持监听信道，只有空闲时才会扣除倒计时，倒计时结束后立即发送帧
	- 接收方
		- 停止等待协议
			- 每收到一个正确数据帧都返回ACK
			- 若发送方超时未收到则“随即退避”
	- ![[Pasted image 20251229162146.png]]
- 帧间间隔IFS（Inter Frame Gap）
	- DIFS
		- 分布式协调IFS
		- 最长的IFS，每次“帧事务”开始之前需要等待的时间
	- SIFS
		- 最短的IFS，收到一个帧后需要预留的一段处理时间
	- PIFS
		- 中等的IFS

- 解决隐藏站问题
	- 信道预约机制（可选）
		1. 发送方广播RTS控制帧（先听后发，忙则退避）
		2. AP广播CTS控制帧（需在RTS、CTS中指明预约时长）
		3. 其他无关节点收到CTS后自觉禁言一段时间（虚拟载波监听机制），发送方收到CTS后发送数据帧
		4. AP收到数据帧后，进行CRC校验，若无差错就返回ACK帧
	- ![[Pasted image 20251229162813.png]]
	- 在IEEE 802.11中规定了数据帧达到怎样的长度才启用预约机制
