## Part 2 文件的逻辑结构
- 逻辑结构与物理结构
	- 逻辑结构
		- 用户眼里文件数据组织方式
	- 物理结构
		- 操作系统眼里文件数据如何放在外存
### 1. 无结构文件
- 由一系列二进制流或字符流组成
- 也叫“流式文件”，如txt文件

### 2. 有结构文件
- 由一组相似的记录组成。“记录式文件”
- 一般，每条记录有一个数据项作为关键字
	- 记录
		- 定长记录
		- 可变长记录
#### 顺序文件
- 逻辑上顺序排列
- 顺序存储
	- 逻辑上相邻，物理上也相邻
	- 可变长记录无法实现随机存取
		- 可变长记录的记录长度不确定，需要从前面的记录推，每次只能从第一个依次往后查找
	- 定长记录可实现随机存取
		- 串结构（记录之间的顺序与关键字无关）：无法快速找到
		- 顺序结构（按关键字顺序排列）：可以快速找到某关键字对应的记录
- 链式存储
	- 逻辑上相邻，物理上不一定相邻
	- 无法实现随机存取，只能从第一个开始找
#### 索引文件
- 建立一张索引表加快文件检索速度，每条记录对应一个索引项
- 索引表本身是定长记录的顺序文件，每当要增加/删除一个记录时，需要对索引表进行修改
	- 可以将关键字作为索引号的内容
- 主要用于
	- 对信息处理的及时性要求比较高的场合
- 使用
	- 可以用不同的数据项建立多个索引表，例如根据姓名建立一张索引表...
- ![Pasted image 20251221133946](images/Pasted%20image%2020251221133946.png) 
#### 索引顺序文件
- 为文件建立一张索引表，但不是每个记录对应一个索引表项，而是一组记录对应一个索引表项
- ![Pasted image 20251221133909](images/Pasted%20image%2020251221133909.png)

- 效率分析
	- 假如有10000个记录，如果顺序文件查找，需要5000次
	- 如果索引顺序文件，分为100组，每组100记录（每组派出一个代表进入索引表）
		- 找到对应分组（50次）
		- 组内查找（50次）
		- 一共100次

- 多级索引顺序文件
	- 假如有$10^6$个记录，用索引顺序文件，分为1000组，1000个记录，需要1000次，还是很多
	- 使用多级索引顺序文件，顶级索引表100，低级索引表100组，每组100个记录
		- 150次
	- ![Pasted image 20251221134538](images/Pasted%20image%2020251221134538.png)

### 3. 索引结点
- 对文件控制块的优化
- 用户查找文件时，只需要用到“文件名”信息
	- 将除了文件名之外的数据放在文件名对应的索引结点中
	- ![Pasted image 20251221145207](images/Pasted%20image%2020251221145207.png)
	- ![Pasted image 20251221145146](images/Pasted%20image%2020251221145146.png)

## Part 4 文件的物理结构
- 操作系统需要对磁盘块的管理
	- 对非空闲磁盘块的管理
		- 即存放了文件数据的磁盘块
		- 由“文件的物理结构/分配方式”处理
	- 对空闲磁盘块的管理
		- 由“文件存储空间管理”处理

- 文件分配方式
	- 即，文件数据应该怎样放在外存中
	- 文件块、磁盘块
		- 一般大小与内存块、页面的大小相同
			- 方便数据交换
		- 和内存类似
### 1. 连续分配
- 每个文件在磁盘上占有一组连续的块
	- 逻辑上连续，物理上也连续
- 物理块号=起始块号+逻辑块号
	- 文件目录项
		- ![Pasted image 20251221151712](images/Pasted%20image%2020251221151712.png)
- 给出逻辑块号就能算
- 优点
	- 支持连续访问和直接访问（随机访问）
	- 文件在顺序读/写时速度最快
		- 每个文件在磁盘上占有一组连续的块
- 缺点
	- 不方便拓展
		- 假如A的大小从3-->4，就需要将A全部移动到其他位置
	- 存储空间利用率低，会产生难以利用的磁盘碎片
		- 用紧凑来处理碎片需要耗费很大的时间代价

### 2. 链接分配
- 隐式链接
	- 文件目录项
		- ![Pasted image 20251221152520](images/Pasted%20image%2020251221152520.png)
	- 除了文件的最后一个磁盘块之外，每个磁盘块都会保存指向下一个盘块的指针，指针对用户透明
	- 缺点
		- 只支持顺序访问，不支持随机访问
		- 指向下一个盘块的指针耗费存储空间
	- 优点
		- 方便磁盘拓展
		- 无碎片问题，外存利用率高
			- 所有的空闲磁盘块都可以被利用
- 显式链接
	- 将用于链接文件各物理块的指针显式的存放在一张表中
		- 即文件分配表（FAT，File Allocation Table）
			- 各个表项在物理上连续存储且长度相同
			- 物理块号可以隐含（其实算是逻辑块号）
			- ![Pasted image 20251221153346](images/Pasted%20image%2020251221153346.png)
	- 文件目录项
		- ![Pasted image 20251221153224](images/Pasted%20image%2020251221153224.png)
	- 一个磁盘一张FAT，开机时将FAT读入内存常驻

- 步骤
	1. 文件名找到起始块号
	2. 判断是否越界（要求大于0）
	3. 查询FAT
	4. 找到逻辑块对应的物理块号
	- 逻辑块号转换成物理块号的过程不需要磁盘操作

- 优点
	- 支持随机访问
	- 块号转换不同访问磁盘，速度快很多
	- 不会产生外部碎片
	- 方便拓展
- 缺点
	- 文件分配表占用一定的存储空间
### 3. 索引分配
 - 索引分配允许文件离散地分配在各个磁盘块中，系统会为每个文件建立一张索引表
	 - 索引表中记录了文件地各个逻辑块对应的物理块（类似内存管理中的页表）
	 - 索引表存放的磁盘块为索引块；文件数据存放的磁盘块为数据块
	 - 目录中记录文件的索引块![Pasted image 20251221185539](images/Pasted%20image%2020251221185539.png)
	 - 根据索引块找到对应的索引表![Pasted image 20251221185654](images/Pasted%20image%2020251221185654.png)
	 - 显式链接分配是一个磁盘对应一张FAT
		 - 基本单位不同，索引是以文件为单位，显式链接是以磁盘为单位

- 步骤
	1. 找到FCB
	2. 找到对应的索引块
	3. 找到索引表
	4. 通过逻辑块号找到对应的物理块号

- 优点
	- 支持随机访问
	- 文件拓展也容易实现
		- 给文件分配一个空闲块并增加一个索引表项即可![Pasted image 20251221190730](images/Pasted%20image%2020251221190730.png)
- 缺点
	- 索引表需要占用一定的空间

- 假如一个文件的大小超过了256块，一个磁盘装不下整张索引表
	- 链接方案
		- 将多个索引块链接起来存放
		- ![Pasted image 20251221191211](images/Pasted%20image%2020251221191211.png)
		- 先读入第一个索引块，再根据第一个索引块的内容将第二个索引块读入内存
		- 假如文件大小为256\*256KB，即256×256个磁盘块（索引项），需要256个索引块来存储，用链接方案连起来
		- 缺点
			- 必须顺序访问，如果需要的是最后一个逻辑块，十分低效
				- 上面的例子需要两百多次磁盘I/O
	- 多层索引
		- 类似多级页表
		- 第一层索引块指向第二层索引块，....
		- 两层索引
			- ![Pasted image 20251221192711](images/Pasted%20image%2020251221192711.png)
		- 只需要3次磁盘I/O
		- K层索引结构需要K+1次读磁盘操作
	- 混合索引
		- 一个文件的顶级索引表中，既包含直接地址索引（直接指向数据块），又包含一级间接索引（指向单层索引表），两级间接索引（指向两层索引表）
		- ![Pasted image 20251221193340](images/Pasted%20image%2020251221193340.png)

- 对比
	- ![Pasted image 20251221193435](images/Pasted%20image%2020251221193435.png)

## Part 5 文件存储空间管理
- 对空闲磁盘块的管理

### 1. 存储空间的划分与初始化
- 文件卷（逻辑卷）
	- 即逻辑上的磁盘分区
	- 可以由多个物理磁盘组成
- 存储空间的划分
	- 将物理磁盘划分为一个个文件卷
- 存储空间初始化
	- 将各个文件卷划分为目录区、文件区
- ![Pasted image 20251221195653](images/Pasted%20image%2020251221195653.png)
### 2. 管理方法
- 用什么方式记录、组织空闲块？
- 如何分配磁盘块？
- 如何回收磁盘块？
#### 空闲表法
- 适用于连续分配方式
- ![Pasted image 20251221195937](images/Pasted%20image%2020251221195937.png)
- 如何分配
	- 可以使用首次适应（10）、最佳适应（18）、最坏适应（10）算法来决定分配区间（以上图为例，假设请求3个块）
- 如何回收
	- 相邻合并
#### 空闲链表法
- 分类
	- 空闲盘块链
		- 操作系统保存链头、链尾指针
		- 分配
			- 从链头开始依次分配，同时修改链头指针
		- 回收
			- 需要回收的盘块依次挂到链尾，同时修改链尾指针
		- 适用于离散分配的物理结构
	- 空闲盘区链
		- 操作系统保存链头、链尾指针
		- 分配
			- 如果申请K个盘块，采用首次适应、最佳适应、最坏适应等算法从链头开始检索直到找到一个符合要求的
			- 可以将不同盘区的盘块同时分配给一个文件
			- 分配完后需要修改相应的链指针、盘区大小
		- 回收
			- 相邻盘区要合并，如果不相邻就挂到链尾
		- 离散分配、连续分配都适用
- 区别
	- ![Pasted image 20251221200539](images/Pasted%20image%2020251221200539.png)

#### 位示图法
- 数据模拟实际情况
	- ![Pasted image 20251221201448](images/Pasted%20image%2020251221201448.png)
- 分配K个块
	- 顺序扫描位示图，找到K个相邻的"0"
	- 根据字号、位号算出对应盘块号
	- 相应位置1
- 回收
	- 盘块号计算字号和位号
	- 置0
- 连续分配、离散分配都适用
#### 成组链接法
- 空闲表、空闲链表不适用大型文件系统
- UNIX使用成组链接法
- 文件目录区中专门用一个磁盘块作为“超级块”，
	- 当系统启动时需要将超级块读入内存，同时内存与外存中的超级块要求一致
	- 超级块
		- 记录了下一组空闲盘块的数量和对应的盘块号
		- 充当一个链头的作用
		- -1（特殊值）表示已经没有下一组空闲块
		- ![Pasted image 20251221202408](images/Pasted%20image%2020251221202408.png)
- 分配
	- 检查第一个分组的块数是否足够
		- 假如需要1个，足够，修改相应数据
		- 假如需要100个，足够，全部分配出去
			- 但是300号内存放了下一组的信息，所以需要将300号的数据复制到超级块中
			- ![Pasted image 20251221202859](images/Pasted%20image%2020251221202859.png)

- 回收
	- 假如一个分组最多100个空闲块，此时第一个分组已经有99个块，还需回收一块
		- 插到第一个分组当中即可
	- 假如第一个分组已有100个空闲块
		- 将新回收的块作为一个新的分组
		- 将超级块中的内容复制到新回收的块中
		- 再将超级块的数据改为新回收的块的块号（2条数据，包括空闲块数量）
			- 原来有101条

## Part 6 文件的基本操作
- 向上提供的几个最基本的功能

- 创建create
	- 需要的参数
		- 所需外存空间大小
		- 文件存放路径
		- 文件名
	- 操作
		- 在外存中找到文件所需的空间（分配外存空间）
			- 空闲表法，位示图、...
		- 根据文件存放路径找到目录，在目录中*创建该文件对应的目录项*（创建目录项）
- 删除delete
	- 参数
		- 文件存放路径
		- 文件名
	- 操作
		- 根据路径找到目录文件，从目录中找到文件名对应的目录项
		- 根据目录项记录的在外存的存放位置，文件大小等信息，*回收文件占用的磁盘块*
		- 从目录中删除文件对应的目录项
- 读read
	- 从外存读入内存并显示在屏幕上
	- 操作
		- 指明哪个文件
			- 如果支持打开文件操作，只需提供文件在打开文件表中的索引号
		- 指明要读入多少数据
		- 指明读入的数据放在内存的位置
	- 操作系统会从读指针指向的外存中将用户指定大小的数据读入用户指定的内存区域中
- 写write
	- 将文件数据从内存写回外存
	- 操作
		- 指明哪个文件
			- 如果支持打开文件操作，只需提供文件在打开文件表中的索引号
		- 指明要写出多少数据（写出数据量）
		- 指明写回外存的数据放在内存的位置
	- 操作系统会从用户指定的内存区域中将写指针指向的外存中
- 打开open
	- 参数
		- 文件存放路径
		- 文件名
		- 要对文件的操作类型（r只读；rw读写...）
	- 操作
		- 根据文件存放路径找到对应的目录文件，从目录中找到文件名对应的目录项，检查是否有指定的操作权限
		- 将目录项复制到内存中的"打开文件表"中。
			- 将对应表的目录编号返回给用户
			- 用户使用打开文件表的编号（索引号/文件描述符）指明要操作的文件
	- 打开文件后进程操作文件就不用重新查目录，加快文件的访问速度
	- 打开文件表
		- 有两种：系统的打开文件表（特有属性：打开文件表）；具体进程的打开文件表（特有属性：读写指针、访问权限）
			- 如果在系统的打开文件表中，无法进行删除操作
			- ![Pasted image 20251221230636](images/Pasted%20image%2020251221230636.png)
- 关闭close
	- 操作
		- 将进程的打开文件表相应表项删除
		- 回收分配给该文件的内存空间等资源
		- 系统打开文件表的打开计数器count-1，若count=0，则删除对应表项

## Part 7 文件共享和保护
### 1. 文件共享
- 文件共享
	- 意味着系统中只有一份文件数据，某个用户修改了其他用户也能看到
- 基于索引结点的共享方式（硬链接）
	- ![Pasted image 20251221232630](images/Pasted%20image%2020251221232630.png)
	- 索引结点中设置了一个链接计数变量count，用于表示链接到本索引上的用户目录项数。
	- 如果某个用户决定删除文件，只用删除用户目录中的文件即可，并将count-1
	- 如果count=0，系统负责删除文件

- 基于符号链的共享方式（软链接）
	- 创建了一个新的文件（link文件）存放目标文件的路径
	- 类似“快捷方式”![Pasted image 20251221233140](images/Pasted%20image%2020251221233140.png)
	- 速度比硬链接方式更慢
		- 需要查询多级目录，会有多次磁盘I/O

### 2. 文件保护
- 口令保护
	- 为文件设置一个口令
	- 口令一般存放在FCB或索引结点中，操作系统将用户输入的口令与FCB中存储的口令对比
	- 优点
		- 保存口令的空间开销小，验证口令的时间开销小
	- 缺点
		- 口令放在系统内部，不安全
- 加密保护
	- 使用加密算法对文件进行加密，访问文件时需要提供正确的密码才能对文件正确解密
	- ![Pasted image 20251221233932](images/Pasted%20image%2020251221233932.png)
	- 优点
		- 保密性强，不用在系统中存储密码
	- 缺点
		- 编码/译码（加密/解密）需要花费一定时间
- 访问控制
	- 在每个文件的FCB（或索引结点）中增加一个访问控制列表（ACL，Access-Control List）
		- 记录各个用户可以对文件执行的操作
	- 访问类型
		- ![Pasted image 20251221234327](images/Pasted%20image%2020251221234327.png)
	- 精简的访问列表
		- 以组为单位，标记各组可以对文件执行哪些操作
		- 系统管理员、文件主、文件主组员、其他用户、...![Pasted image 20251221234505](images/Pasted%20image%2020251221234505.png)
