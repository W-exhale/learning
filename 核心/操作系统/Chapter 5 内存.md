### 2. 装入
- 如何实现地址转换（即，将逻辑地址转化为物理地址）
	- 绝对装入
		- 编译的时候就将逻辑地址改为物理地址
		- 只适用于单道程序的运行环境
		- 编译器负责
	- 可重定位装入（静态重定位）
		- 将装入模块（可执行文件）装入内存时对地址进行重定位（加入+100）
		- 装入程序负责
		- 用于早期的多道批处理系统
		- 缺点
			- 地址空间必须时连续的，且需要一次全部装入内存
			- 在程序运行期间不可以移动，也不能再申请内存空间
	- 动态运行时装入（动态重定位）
		- 将装入模块装入内存时还是使用逻辑地址，将地址转换往后推到程序真正要执行的时候进行。
		- 现代操作系统
		- 需要一个重定位寄存器
			- 存放装入模块的起始位置
				- 假如在物理地址从100开始，逻辑地址从0开始
				- 那么重定位寄存器中存100
				- 实际使用的时候将逻辑地址与该重定位寄存器相加即可
				- 可以随时修改
		- 优点
			- 将程序分配到不连续的存储区中
			- 动态申请分配内存
			- 便于程序段共享，可以像用户蹄冻一个比存储空间大得多的地址空间

## Part 2 内存分配
### 1. 连续分配管理
- 为用户进程分配一个连续的内存空间
#### 单一连续分配
- 内存被分为系统区和用户区
	- 系统区
		- 内存的低地址部分，存放操作系统的相关数据
	- 用户区
		- 存放用户进程相关数据
- 内存中只能有一道用户程序，用户独占整个用户区空间
- ![[Pasted image 20251218093847.png|400]]
- 优点
	- 实现简单，无外部碎片
	- 可以采用覆盖技术扩充内存
	- 不一定需要内存保护（早期的PC操作系统MS-DOS）
- 缺点
	- 只用于单用户、单任务的操作系统
	- 有内部碎片
		- 分配给某进程内存区域中没有用上的内存碎片
	- 存储器利用率极低

#### 固定分区分配
- 将用户空间划分为若干个固定大小的分区，在每个分区中只装入一道作业。
- 两种
	- 分区大小相等
		- 缺乏灵活性，如果内存不够，需要使用内存扩充，适用于用一台计算机控制多个相同对象的场合
	- 分区大小不等
		- 增加灵活性
- ![[Pasted image 20251218103616.png|300]]
- 需要建立一个分区说明表，来实现各个分区的分配与回收，包括对应分区的大小、起始地址、状态（是否已分配）
- 优点
	- 实现简单，无外部碎片
- 缺点
	- 当用户程序太大时，就需要采用覆盖技术，但是会降低性能
	- 会产生内部碎片，内存利用率低
#### 动态分区分配
- 不会预先划分内存分区，在进程装入内存时根据进程的大小动态建立分区，使分区大小正好适合进程需要。

##### 动态分区分配算法
- 当有很多个空闲分区时，应该选择哪个分区进行分配
1. 首次适应算法（First Fit）
	- 算法思想
		- 每次从低地址开始查找，第一个满足大小的空闲分区
	- 实现
		- 空闲分区以*地址*递增的次序排列。分配内存时顺序查找空闲分区链（空闲分区表），找到第一个即可
	- 效果最好
2. 最佳适应算法（Best Fit）
	- 优先使用更小的空闲区
	- 实现
		- 按*容量*递增次序链接，每次分配时顺序查找空闲分区链（空闲分区表），选第一个
	- 缺点
		- 每次选最小的，会留下越来越多的外部碎片
3. 最坏适应算法（Worst Fit）
	- 优先使用更大的空闲区
	- 实现
		- 按容量递减，选第一个
	- 缺点
		- 大进程到达无法使用
4. 邻近适应算法（Next Fit）
	- 和首次适应算法很像，首次适应算法每次从头查，该算法从上次查找结束的地方开始查
	- 实现
		- 空闲分区以地址递增的顺序排列（循环链表），每次从上一个结束的地方开始查，找到第一个空闲分区。
	- 优点
		- 不用对链表重新排列
	- 缺点
		- 高地址的部分的大空闲分区被使用的概率较大

### 2. 非连续分配管理
- 可以用户进程分配一些分散的内存空间
#### 1. 基本分页存储管理
##### 基本概念
- 分页存储
	- 页框（page frame）
		- 将内存空间分为一个个大小相等的分区（比如每个分区4kb），每个分区就是一个“页框”（页框=页帧=内存块=物理块=物理页面）。每个页框有一个编号——“页框号”，从0开始
		- 内存在物理上被划分的一个个部分
	- 页面
		- 将进程的逻辑地址空间分为与页框大小相等的一个个部分，每个部分称为“页”或“页面”。每个也页面有一个编号——“页号”，从0开始、
		- 进程在逻辑上被划分的一个个部分
	- 操作系统以页框为单位为各个进程分配内存空间，进程的每个页面分别放入一个页框中。
		- 即进程的页面与页框是一一对应的关系
		- 不用连续存放
			- ![[Pasted image 20251218150622.png]]
- 页表
	- 记录实际页框和进程页面的一一对应（映射）关系
	- 一个进程对应一张页表（存放在PCB中）
	- 进程的每个页面对应一个页表项（由页号+块号组成）![[Pasted image 20251218151337.png]]
- 问题
	- 每个页表项占多少字节？（即内存块的数量  ）
		- ![[Pasted image 20251218152045.png]]
		- 页表项在内存中连续存放，所以页号可以隐含，页号不占空间（类似数组下标）；块号占空间
	- 如何实现地址的转换？
		- 方法
			1. 确定逻辑地址A对应的“页号”P，相除
			2. 找到P号页面在内存中的起始地址（需要查页表）
			3. 确定逻辑地址A的“页内偏移量”W，取余
			4. A对应的物理地址=P号页面在内存中的起始地址+页内偏移量W
		- 计算
			- 页号为红色部分，偏移量为黑色部分![[Pasted image 20251218152815.png]]

##### 基本地址变换机构
- 用于实现逻辑地址到物理地址转换的一组硬件机构
- 通常会在系统中设置一个*页表寄存器（PTR）*，存放页表在内存中的起始地址F和页表长度M。进程未执行时，F和M放在进程控制块（PCB）中，当进程被调度时，将F和M放到PTR中。

- 转换过程
	- ![[Pasted image 20251218164315.png]]
	1. 计算页号P和页内偏移量
	2. 比较页号P和页表长度，如果越界则产生越界中断，否则继续执行
	3. 查页表找到对应块号
	4. 计算物理地址，页号和偏移量转换为二进制拼接可得
	5. 访问目标内存单元

##### 具有快表的地址变换机构
- 基本地址变换机构的改进版本
	- 加快地址变换的过程

- 什么是快表（TLB）？
	- 快表，即联想寄存器（TLB，translation lookaside buffer）
	- 一种访问速度比内存快很多的高速缓存（不是内存！）
	- 用来存放最近访问页表项的副本，可以加速地址变换的速度
	- 与之对应的内存中的页表称为*慢表*
![[Pasted image 20251219094131.png|300]]


- 引入快表的地址变换过程
	- ![[Pasted image 20251219094712.png]]
	1. CPU给出逻辑地址，计算出页号和页内偏移量，将页号与快表中的页号比较
	2. 如果和快表对上，则直接取该页对应的内存块号，和偏移量拼接得到物理地址，访问对应内存单元
	3. 如果没对上，则访问内存中的页表，找到对应页表项（同时将其存入快表，如果已满根据相关算法进行替换）
- 进程切换时，快表的内容也需要被清除

- 局部性原理
	- 因为局部性原理，一般快表的命中率达到90%以上。
	- 时间局部性
		- 如果执行了程序的某条指令，不久后这条指令很有可能再次执行；某个数据被访问过，不久后可能再次被访问（因为程序中存在大量的循环）
	- 空间局部性
		- 如果程序放问了某个存储单元，不久后其附近的存储单元可能被访问（很多数据都是连续存储）
	- 所以由于时间和空间上的局部性，可能连续很多次查到的都是同一个页表项

##### 两级页表
- 单级页表的问题，如何解决？
	- 页表*连续存放*，当页表很大时需要占用很多个连续的页框
		- 参考页表的由来，就是为了实现非连续分配
		- 当单级页表占用很多个连续页框时可以使用相同的思路，再加一级页表来定位第一级页表
			- 即 为离散分配的页表再建立一张页表，称为页目录表（外层页表、顶层页表）
	- 由局部性原理可知，进程在一段时间内只需要访问某几个页面，就可以运行，没必要让整个页表都常驻内存
		- 可以在需要访问页面时才把页面调入内存（虚拟存储技术）。
		- 在页表项增加一个标志位，表示该页面是否已经调入内存
		- 如果想要访问的页面不在内存，则发生缺页中断（内中断），然后将目标页面从外存调入内存

#### 2. 基本分段存储管理
- 与分页区别
	- 离散分配时所分配地址空间的基本单位不同

- 概念
	- 分段
		- 类似分页管理中的分页
		- 按照程序的逻辑功能划分若干个段，每段从0开始编址
		- 内存分配原则
			- 以段为单位进行分配，每个段在内存中占据连续空间，各个段之间可以不相邻 
			- 编译程序会将段名转换为段号
		- 组成
			- 由段号和段内地址（段内偏移量）组成
				- 段号决定每个进程最多多少段
				- 段内偏移量决定每个段的最大长度
		- 步骤
			- 下面D、X之类的段名被编译程序翻译为对应段号
			- `<A>、<B>`单元被翻译为段内地址
		- ![[Pasted image 20251220211546.png]]
	- 段表
		- 类似分页管理中的页表
		- 即逻辑段对应物理内存的段映射表
		- 组成
			- 段号、段长、基址
			- 每个页框（或页面）都相等所以不用表示，每个段不等，需要表示
		- ![[Pasted image 20251220212656.png]]
		- 注意
			- 每个段表项记录了该段在内存中的起始地址（基址）和段长
			- 各个段表项的长度相同
				- 段号也不占存储空间

- 地址变换
	1. 根据逻辑地址得到段号、段内地址
	2. 判断段号是否越界（大于等于越界）
	3. 查询段表
	4. 比较段内地址和段长，判断是否越界（大于等于越界）
	5. 计算得物理地址
	6. 访问内存单元
	- ![[Pasted image 20251220213706.png]]

- 分段与分页对比
	- 页
		- 是信息的物理单位
		- 主要目的
			- 实现离散分配，提高内存利用率
		- 系统管理上的需要，完全是系统行为，大小固定且由系统决定
		- 一维的，直接得到对应内存块地址（块号）
		- 对用户不可见
	- 段
		- 信息的逻辑单位
		- 主要目的
			- 更好的满足用户需求
		- 一个段包含一个逻辑模块的信息
		- 长度不固定，取决于用户编写的程序
		- 二维的，需要段长和基址（该段对应的模块在内存的起始地址）
		- 对用户可见，用户编程时需要显式给出段名
	- 分段比分页更容易实现信息的共享和保护
		- 实现共享：将段表项设置为相同的即可
			- 可共享内容：不能被修改的代码（纯代码、可重入代码）
		- 保护
			- ![[Pasted image 20251220214712.png]]
- 访存次数
	- 分页：n级+1次
		- 引入快表减少次数
	- 分段：两次
		- 访问段表+访问目标单元
		- 也可以引入快表

## Part 3 虚拟内存
### 1. 基本概念
- 用于内存空间的扩充

- 传统管理方式的特征、缺点
	- 连续分配和非连续分配
	- 特征与缺点
		- 一次性
			- 作业必须一次性全部转入内存后才能开始运行
			- 问题
				- 作业太大无法装入
				- 无法同时容纳所有作业，降低并发度
		- 驻留性
			- 一旦被装入就会一直留在内存中，直至作业运行结束
			- 一个时间段内只需要作业的一小部分数据

- 局部性原理
	- 时间局部性
		- 执行了某条指令，之后可能再次执行
		- 访问了某个数据，之后可能再次访问
	- 空间局部性
		- 访问了某个存储单元，其附近的存储单元之后可能被访问
			- 很多数据和指令在内存中连续存放
	- 高速缓存技术
		- 使用更频繁的数据放到更高速的存储器中![[Pasted image 20251220222928.png|400]]


- 虚拟内存的定义和特征
	- 定义
		- 在操作系统管理下，在用户看来似乎有比实际内存大的内存，这就是虚拟内存
			- 程序装入时，将很快用到的部分装入内存，暂时用不到的留在外存
			- 信息不在内存时，操作系统从外存调入内存
			- 内存空间不够时，操作系统将内存中暂时用不到的信息换出外存。
	- 特征
		- 多次性
			- 多次调入内存
		- 对换性
			- 允许在作业运行过程中换入换出
		- 虚拟性
			- 从逻辑上扩充了内存的容量，使用户看到的内存容量大于实际容量

- 如何实现
	- 建立在离散分配的内存管理分配方式
		- 需要允许一个作业分多次调入内存，连续分配方式不易实现
	- 实现
		- 请求分页存储管理
		- 请求分段存储管理
		- 请求段页式存储管理
	- 与非连续分配区别
		- 当信息不在内存时需要操作系统从外存调入内存
			- 操作系统需要提供请求调页（调段）功能
		- 内存不够需要操作系统将暂时用不到的信息换出到外存
			- 操作系统提供页面（段）置换功能


### 2. 请求分页管理方式
- 页表机制
	- 从外存调入
		- 判断页面是否已调入，未调入的外存地址
	- 调出内存
		- 调哪个页面；
		- 是否被修改过，若修改过则外存数据也要修改，未修改则不用修改外存
	- ![[Pasted image 20251220235339.png]]

- 缺页中断机构
	- 当要访问的页面不在内存时，会产生一个缺页中断
	- 然后由操作系统的缺页中断处理程序处理中断
	- 同时，缺页的进程中断，进入阻塞队列，
	- 调页完成后再唤醒，放回就绪队列。
	- ![[Pasted image 20251221000021.png]]
		- 如果有内存块，则直接分配一个空闲块，修改页表中对应的页表项![[Pasted image 20251221000208.png]]
		- 如果没有空闲块，由页面置换算法选择一个页面淘汰，如果修改过，则需要写回外存；未修改过就不用
- 缺页中断
	- 属于内中断中的故障（fault），由错误条件引起，可能被故障处理程序修复的
	- 一条指令再执行期间可能产生多次缺页中断
		- copy A to B：A和B都不在，则可能发生2次缺页中断

- 地址变换机构
	- 新增
		- 请求调页（查到页表项时进行判断）
		- 页面置换（需要调入页面但无空闲块）
		- 需要修改请求页表中的新增表项
	- ![[Pasted image 20251221001156.png]]
	- ![[Pasted image 20251221001343.png]]
		1. 只有“写”指令才需要修改“修改位”，一般只需要修改快表中的数据，只有快表项删除时才需要写回内存中的慢表，可以减少访存次数
		2. 中断处理程序需要保留CPU现场
		3. 使用页面置换算法选择页面换出
		4. 换入/换出页面都需要慢速I/O操作，如果过于频繁，会有很大的开销
		5. 页面调入内存后需要修改慢表，同时也需要复制到快表中

### 3. 页面置换算法
- 决定应该换出哪个页面
	- 页面的换入换出需要磁盘I/O，开销较大，好的页面置换算法追求更少的缺页率
	- 缺页率=缺页中断次数/访存次数

#### 最佳置换算法（OPT，optimal）
- 每次选择淘汰的页面以后永不使用或是在最长时间内不在被访问的页面，保证最低的缺页率

#### 先进先出置换算法（FIFO）
- 淘汰最在进入内存的页面
- 实现
	- 将调入的内存根据先后顺序排成一个队列，需要调出时，队头出去即可
- Belady异常
	- 当为进程分配的物理块数增大时，缺页次数不减反增的现场
- 只有FIFO会发生Belady异常，算法性能差
#### 最近最少使用置换算法（LRU，least recently used）
- 淘汰最近最久未使用的页面![[Pasted image 20251221092921.png]]
- 实现
	- 在页表项中用*访问字段*记录页面上次被访问以来所经历的时间t，需要淘汰时选择t最大的淘汰
- 性能好，实现困难，开销大，很吃硬件

#### 时钟置换算法（ClOCK）
- 也叫最近未用算法（NRU，Not Recently Used）![[Pasted image 20251221092907.png]]
- 实现
	- 为每个页面设置一个*访问位*，内存中的页面通过链接指针链接成一个循环队列。当某页被访问时，访问位置为1；
	- 需要淘汰时看访问位，如果为0就换出，如果是1，就置0不换出；
	- 如果第一轮扫描都是1，则全部置0后进行第二轮扫描
- 改进型的时钟置换算法
	- 简单的时钟置换只考虑最近是否访问，这里加上只有淘汰的页面被修改过才需要写回外存
		- 即在其他条件都相等时优先淘汰没有修改过的页面
		- 方便讨论，用（访问位，修改位表示页面状态）
	- 实现
		- 将所有可能被置换的页面排成循环队列
		- （0，0）用于于替换，假如无（0，0），不修改任何标志位进行第二轮扫描
		- 查找（0，1），假如无将所有扫描过的访问位置0，进行第三轮
		- 查找（0，0），不修改任何标志位
		- 查找（0，1）用于替换
		- 最多进行4轮扫描

### 4. 页面分配策略
- 驻留集
	- 请求分页存储管理中给进程分配的物理块的集合
	- 采用了虚拟存储技术的系统中，驻留集的大小小于进程的总大小
		- 驻留集太小，缺页频繁
		- 太大，并发度下降，资源利用率降低
- 概念
	- 分配
		- 固定分配
			- 驻留集大小不变（进程运行期间）
		- 可变分配
			- 驻留集大小可变
	- 置换
		- 局部置换
			- 发生缺页时只能选进程自己的物理块进行置换
		- 全局置换
			- 可以将操作系统保留的空闲块分配给缺页进程
			- 或将别的进程持有的物理块置换到外存，再分配给缺页进程
			- 意味着一个进程用的物理块数一定会改变，因此不可能是固定分配
- 页面分配、置换策略
	- 固定分配局部置换
		- 系统为每个进程分配一定数量的物理块，整个运行期间不变，如果发生缺页则从该进程在内存中的页面中选出一页换出，再调入需要的页面
		- 缺点
			- 很难确定刚开始分配多少物理块合理
	- 可变分配全局置换
		- 刚开始分配一定数量的物理块，操作系统保持一个空闲物理块队列。缺页时从空闲块中取出一块分配给进程，若无空闲物理块则选择一个未锁定的页面换出外存，再将该物理块分配给进程
		- 缺点
			- 只要进程发生缺页就会获得新的物理块，只有空的物理块用完才会发生置换
			- 被选中调出物理块的进程拥有的物理块会减少，缺页率会增加
	- 可变分配局部置换
		- 缺页时只允许从该进程自己的物理块中选出一个换出外存；如果频繁缺页，系统就为该进程多分配几个物理块直到进程缺页率到适当程度；如果缺页率特别低，也可适当减少分配的内存块
		- 特点
			- 根据缺页频率控制物理块数量
- 调入页面的时机
	- 预调页策略
		- 预测不久后可能访问到的页面，预先调入内存，但是目前成功率只有50%
			- 根据局部性原理（空间局部性），一次性调入若干个相邻页面比一次调入一个页面更高效，但是如果大多都没用则很低效
		- 这种策略主要用于进程的首次调入，由程序员决定先调入哪些部分
	- 请求调页策略
		- 再运行期间发现缺页时将所缺页面调入
			- I/O开销大，每次都要磁盘I/O操作
- 从何处调页
	- 从外存（磁盘）![[Pasted image 20251221100935.png|400]]
	- 如果对换区空间够
		- 页面调入调出都是内存和对换区进行的
		- 保证了速度
		- 进程运行前需要将进程相关数据从文件区复制到对换区
	- 如果对换区不够
		- 不会被修改的数据直接从文件区调入
			- 该数据不用写回磁盘
		- 可修改的数据唤出时需要写回磁盘对换区，需要时再从对换区调入
	- UNIX方式
		- 运行之前有关数据都放在文件区，未使用的页面都从文件区调入
		- 换出时换到对换区，需要时从对换区调入

- 抖动（颠簸）现象
	- 刚刚换出的页面马上换入内存；刚刚换入的页面马上换出外存
	- 主要原因
		- 进程频繁访问的页面数目高于可用的物理块数（分配给进程的物理块不够）
- 工作集
	- 在某段时间间隔里，进程实际访问页面的集合
	- 操作系统根据窗口尺寸来计算工作集![[Pasted image 20251221101915.png]]
	- 系统通过监测工作集的大小来决定给进程分配多少个内存块
	- 驻留集的大小不能小于工作集的大小，否则将频繁缺页
	- 拓展
		- 页面置换可以选择不在工作集中的页面进行淘汰

### 5. 内存映射文件
- 介绍
	- Memory-Mapped Files
	- 操作系统向上层程序员提供的功能（系统调用）
		- 方便程序员访问文件数据
		- 方便多个进程共享同一个文件

- 传统的文件访问方式
	- open系统调用
		- 打开文件
	- seek系统调用
		- 将读写指针移到某个位置
	- read
		- 从读写指针所指位置读入若干数据
			- 从磁盘读入内存
	- write
		- 将内存中的指定数据写回磁盘
			- 根据读写指针确定要写回什么位置

- 内存映射文件的访问方式
	- open
		- 打开文件
	- mmap
		- 将文件映射到进程的虚拟地址空间
			- 以访问内存的方式访问文件数据
			- 文件数据的读入、写出由操作系统自动完成
			- 进程关闭文件时，操作系统自动将文件被修改的数据写回磁盘
	- 只需要直到文件在内存中的起始地址
- 内存映射文件的作用
	- 实现文件共享
		- 多个进程映射同一个文件，实现文件共享![[Pasted image 20251221124135.png]]

- 特性
	- 可以使用系统调用将文件映射到进程的虚拟地址空间
	- 以访问内存的方式读写文件
	- 关闭文件时，操作系统自动将文件数据写回磁盘，解除内存映射
	- 多个进程映射同一个文件，方便共享
- 优点
	- 编程更简单，已建立映射的文件，按访问内存的方式读写即可
	- 文件数据写入写出由操作系统控制，I/O效率也可以由操作系统优化（预读入、缓写出）
