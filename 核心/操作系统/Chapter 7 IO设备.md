## Part 1 基本概念、分类
- 概念
	- 可以将数据输入/输出计算机的外部设备，属于硬件部件
	- UNIX系统将外部设备抽象成一种特殊文件用户可以使用与文件操作相同的方式对外部设备进行操作

- 按特性
	- 人机交互类
		- 数据传输速度慢
		- 鼠标、键盘、打印机
	- 存储设备
		- 快
		- 移动硬盘、光盘
	- 网络通信设备
		- 之间
		- 调制解调器
- 按传输速率
	- 低速设备
		- 鼠标、键盘
		- 每秒几个-几百字节
	- 中速设备
		- 激光打印机
		- 每秒数千-上万字节
	- 高速设备
		- 磁盘
		- 每秒数千-千兆字节

- 按信息交换的单位
	- 块设备
		- 磁盘
		- 传输单位是“块”，传输速率高，可寻址，即 可随机读写任一块
	- 字符设备
		- 鼠标、键盘
		- 传输单位是“字符”，慢，不可寻址，输入输出是常采用中断驱动方式

- 组成
	- 机械设备
		- 看得见摸得着的
		- 显示器的LED屏、移动硬盘的磁臂、磁盘盘面
	- 电子部件（I/O控制器或设备控制器...）
		- 主板扩充槽的印刷电路板
		- CPU需要通过电子部件来看控制机械部件
## Part 2 I/O控制
### 1. I/O控制器
- 功能
	- 接收和识别CPU发出的命令
		- CPU发来的命令，设备控制器中会有相应的*控制寄存器*来存放命令和参数
	- 向CPU报告设备状态
		- 有相应的*状态寄存器*用于记录I/O设备的当前状态
		- 如1表示空闲，0表示忙碌
	- 数据交换
		- 设置相应的*数据寄存器*，输出时，用于暂存CPU发来的数据，之后再由控制器传送设备；输入时暂存设备发来的数据，之后由CPU取走数据
	- 地址识别
		- 用于区分设备控制器中的各个寄存器，各个寄存器有特定的“地址”，设备控制器通过CPU提供的地址来判断读写哪个寄存器

- 组成
	- ![Pasted image 20251225134022](images/Pasted%20image%2020251225134022.png)
	- 注意
		- 一个I/O控制器可能对应多个设备
		- 各种寄存器也可能有多个
			- 内存映像I/O
				- 有的寄存器占用内存地址的一部分
				- 简化了指令
					- 可以采用对内存的指令来实现对控制器的操作
			- 寄存器独立编址
				- 采用I/O专用地址
				- 需要设置专门的指令来实现对控制器的操作
					- 不仅要指明寄存器地址，也要指明控制器编号

### 2. I/O控制方式
#### 程序直接控制方式
- 完成一次读写操作的流程
	- ![Pasted image 20251225135131](images/Pasted%20image%2020251225135131.png)
	- ![Pasted image 20251225135505](images/Pasted%20image%2020251225135505.png)
- CPU干预的频率
	- 频繁，I/O操作开始之前，完成之后都需要CPU，*在等待I/O完成的过程中需要不断地轮询检查*
- 数据传送的单位
	- 每次读/写一个字
- 数据的流向
	- 读（数据输入）：I/O设备-->CPU（CPU寄存器）-->内存
	- 写（数据输出）：内存-->CPU-->I/O设备
- 主要缺点/优点
	- 优点
		- 实现简单
	- 缺点	
		- CPU和I/O设备之只能串行工作CPU需要一直轮询检查，长期处于“忙等”状态，CPU利用率低

#### 中断驱动方式
 - 引入中断机制
	 - I/O设备速度很慢，因此在CPU发出读/写命令后，可以将等待I/O的进程阻塞
	 - 先切换到别的进程执行。
 - I/O完成后，控制器会向CPU发出一个中断信号
	 - CPU检查中断信号后保存当前进程的运行环境信息，去执行中断处理程序处理中断
	 - 处理中断过程中，CPU从I/O控制器读一个字的数据传到CPU中，再写入主存
 - CPU恢复等待I/O的进程或不管等待的进程先执行别的进程的运行环境，继续执行。

- 注意
	- CPU在每个指令周期的末尾检查判断
	- 中断处理过程中需要保存、恢复进程的运行环境
		- 如果中断频率太高，会降低系统性能

- 完成一次读写操作的流程
	- ![Pasted image 20251225145252](images/Pasted%20image%2020251225145252.png)
- CPU干预的频率
	- I/O操作开始之前，完成之后需要CPU
	- 等待I/O完成的过程中CPU可以切换到别的进程执行
- 数据传送的单位
	- 每次读/写一个字 
- 数据的流向
	- 读（数据输入）：I/O设备-->CPU（CPU寄存器）-->内存
	- 写（数据输出）：内存-->CPU-->I/O设备
- 主要缺点/优点
	- 优点
		- I/O控制器会通过中断信号主动报告I/O已完成，CPU不需要不停的轮询。
		- CPU和I/O设备可以并行工作，CPU利用率up
	- 缺点
		- 每个字在I/O设备与内存之间传续都需要经过CPU，频繁的中断处理会消耗较多的CPU时间

### 2. 设备独立性软件
- 设备无关性软件
	- 与设备的硬件无关的功能在这层实现
- 实现的功能
	- 向上层提供统一的调用接口（如read/write系统调用）
	- 设备的保护
		- 类似文件保护，设备看成特殊文件，不同用户访问权限不一样
	- 差错处理
		- 对一些设备的错误进行处理
	- 设备的分配与回收
	- 数据缓冲区管理
		- 通过缓冲技术屏蔽设备之间数据交换单位大小和传输速度的差异
	- 建立逻辑设备名到物理设备名的映射关系，根据设备类型选择调用相应的驱动程序
		- 逻辑设备名：用户看到的
		- 物理设备名：操作系统看到的
		- 通过逻辑设备表（LUT，Logical Unit Table）来确定物理设备和找到对应的设备驱动程序
			- ![Pasted image 20251225152905](images/Pasted%20image%2020251225152905.png)
		- 管理LUT方式
			- 整个系统只设置一张LUT
				- 意味着所有用户不能使用相同的逻辑设备名，该方法只适用于单用户操作系统
			- 为每个用户设置一张LUT，各个用户的逻辑设备名可以重复

### 3. 设备驱动程序
- 不同的设备需要不同的设备驱动程序
	- 不同设备的内部硬件特性不同，
	- 设备出厂的时候厂家需要提供与设备相对应的驱动程序、CPU执行驱动程序的指令序列
	- 来完成设置设备寄存器，检查设备状态等工作

- 功能
	- 主要负责对硬件设备的具体控制
		- 将上层发出的一系列命令（read/write）转化成计算器能懂的一系列操作
			- 如
				- 设置设备寄存器
				- 检查设备状态
	- 厂家需要根据设备的硬件特性设计并提供相应的驱动程序

- 注意
	- 驱动程序一般以一个独立进程的方式存在

### 1. 假脱机技术（SPOOLing技术）
- 什么是脱机技术？
	- 批处理阶段中用磁带实现脱机输入/输出技术
		- 在外围控制机的控制下慢速输入设备数据先被输入到更快速的磁带上
		- 之后主机从快速的磁带上读入数据
		- ![Pasted image 20251225181601](images/Pasted%20image%2020251225181601.png)
	- 即，脱离主机的控制来进行输入输出操作
- 脱机技术解决的问题？
	- 缓解CPU与慢速I/O设备的速度矛盾。
	- 磁带起到一个长期缓冲的作用
		- 即使CPU在忙碌，也可以提前将数据输入到磁带
		- 即使慢速设备在忙碌，也可以提前将数据输出到磁带

- 假脱机技术
	- 用软件的方式模拟脱机技术
	- 以打印机为例，将独占式打印机虚拟成共享打印机

- 实现原理
	- 输入井和输出井
		- 模拟脱机输入输出的两个磁带
		- 在磁盘上开辟的两个存储区域
		- 用于收容I/O设备输入和用户进程输出的数据
	- 输入进程和输出进程
		- 模拟脱机输入输出的两个外围控制机
		- 需要和用户进程并发执行，必须有多道程序系统的支持
	- 输入缓冲区和输出缓冲区
		- 用于暂存输入输出的数据
		- 在内存的缓冲区中

- 共享打印机的原理分析
	- ![Pasted image 20251225183117](images/Pasted%20image%2020251225183117.png)
	- 当多个用户提出输出打印请求时，系统会答应它们的请求，但不会真的将打印机分配给他们，而是由假脱机管理进程处理
	- 假脱机处理进程步骤
		- 在磁盘输出井中为进程申请一个空闲缓冲区，将要打印的输入送入其中
		- 为用户进程申请一张空白的打印请求表，存放用户打印数据存放位置等信息，将该表挂到假脱机文件队列
		- 打印机空闲时，输出进程就从文件队头取出一张打印请求表
			- 根据表中要求将数据从输出井传送到输出缓冲区，再输出到打印机进行打印

### 2. 设备的分配与回收
#### 设备分配时应该考虑的因素
- 设备的固有属性
	- 独占设备
		- 一个时段只能分配给一个进程（如打印机）
	- 共享设备
		- 宏观上可同时分配给多个进程使用（如磁盘），微观上是交替使用
	- 虚拟设备
		- 采用SPOOLing技术将独占设备改造成虚拟的共享设备（共享打印机）
- 设备分配算法
	- 先来先服务、优先级高者优先、短任务优先、...
- 设备分配中的安全性
	- 安全分配方式
		- 为进程分配一个设备后就将进程阻塞，本次I/O完成后才将进程唤醒。
		- 一个时段内每个进程只能使用一个设备
		- 优点
			- 破环了“请求和保持”条件，不会死锁
		- 缺点
			- 对于一个进程来说，CPU和I/O设备只能串行工作
	- 不安全分配方式
		- 进程发出I/O请求之后，系统为其分配I/O设备，进程可以继续执行，直到某个I/O请求得不到满足时才将进程阻塞
		- 一个进程可以同时使用多个设备
		- 优点
			- 进程的计算任务和I/O任务可以并行处理，使进程迅速推进
		- 缺点
			- 有可能发生死锁（使用银行家算法等避免进入不安全状态）
#### 静态分配与动态分配
- 静态分配与动态分配
	- 静态分配
		- 进程运行前就分配所有资源，运行结束后归还
		- 破环了“请求和保持”条件，不会发生死锁
	- 动态分配
		- 进程运行过程中动态申请设备资源

#### 设备分配的步骤
1. 根据进程请求的物理设备名查找SDT（进程请求分配设备时提供参数）![Pasted image 20251225205054](images/Pasted%20image%2020251225205054.png)
2. 根据SDT找到DCT，若设备忙碌则将进程PCB挂到设备等待队列中，不忙碌则分配给进程![Pasted image 20251225205214](images/Pasted%20image%2020251225205214.png)
3. 根据DCT找到COCT，若控制器忙碌则将进程PCB管道控制器等待队列中，不忙碌则将控制器分配给进程![Pasted image 20251225205341](images/Pasted%20image%2020251225205341.png)
4. 根据COCT找到CHCT，若通道忙碌则将进程PCB挂到通道等待队列中，否则将通道分配给进程![Pasted image 20251225205514](images/Pasted%20image%2020251225205514.png)
5. 当设备、控制器、通道都分配成功时，这次分配才算成功，之后即可启动I/O设备进行数据传送
- 缺点
	- 用户编程时必须使用物理设备名，底层细节对用户不透明（用户需要直到底层细节），不方便编程
	- 若换一个物理设备，则程序无法运行
	- 若进程请求的物理设备正在忙碌，即使有同种设备空闲，进程也必须阻塞等待

- 设备分配步骤的改进
	- 建立逻辑设备名与物理设备名的映射机制，用户编程时只需提供逻辑设备名
	1. 根据进程请求的逻辑设备名查找SDT（逻辑设备名即设备类型）![Pasted image 20251225210323](images/Pasted%20image%2020251225210323.png)
	2. 根据SDT找到用户进程指定类型的、并且空闲的设备，将其分配给进程操作系统再LUT中新增一个表项![Pasted image 20251225210518](images/Pasted%20image%2020251225210518.png)
	3. 根据DCT找到COCT，若控制器忙碌则将进程PCB管道控制器等待队列中，不忙碌则将控制器分配给进程
	4. 根据COCT找到CHCT，若通道忙碌则将进程PCB挂到通道等待队列中，否则将通道分配给进程
	5. 当设备、控制器、通道都分配成功时，这次分配才算成功，之后即可启动I/O设备进行数据传送
	- 如果之后用户进程再次通过相同的逻辑设备名请求设备，操作系统可通过LUT表知道用户进程需要的物理设备和该设备的驱动入口地址

### 2. 磁盘调度算法
#### 一次磁盘读/写操作需要的时间
- 寻找时间（寻道时间）
	- 读/写数据前，将磁头移动到指定磁道所花的时间
		- 启动磁头臂需要时间，s
		- 移动磁头需要时间，假设匀速移动，每跨越一个磁道耗时m，总共跨越m条磁道
	- T=$s+m*n$

- 延迟时间
	- 旋转磁盘，使磁头定位到目标扇区需要的时间，转速r
	- T=$\frac{1}{2}*\frac{1}{r}$
	- ![Pasted image 20251226094751](images/Pasted%20image%2020251226094751.png)

- 传输时间
	- 从磁盘读出或向磁盘写入数据所经历的时间，假设转速为r，读写字节数为b，每个磁道上的字节数为N
	- T=$\frac{1}{r}*\frac{b}{N}$
- 一次磁盘读写的时间
	- 寻道时间+延迟时间+传输时间
		- 延迟时间和传输时间都与磁盘转速（固有属性）相关，且为线性相关

#### 磁盘调度算法
- 直接影响寻道时间
##### 先来先服务（FCFS）
- 根据进程请求访问磁盘的先后顺序
- ![Pasted image 20251226095505](images/Pasted%20image%2020251226095505.png)
- 优点
	- 公平
	- 如果磁道集中，性能还行
- 缺点
	- 如果有大量进程使用磁盘，很分散，则性能很差
##### 最短寻找时间优先（SSTF）
- 最早处理与当前磁头最近的磁道（贪心算法思想）
- ![Pasted image 20251226095758](images/Pasted%20image%2020251226095758.png)
- 优点
	- 性能较好，平均寻道时间短
- 缺点
	- 可能产生“饥饿”现象

##### 扫描算法（SCAN）
- 也叫电梯算法
- 只有磁头移动到最外侧磁道时才能往内移动，移到最内侧才能往外移动
- ![Pasted image 20251226100139](images/Pasted%20image%2020251226100139.png)
- 优点
	- 性能较好，平均寻道时间较短，不会产生饥饿现象
- 缺点
	- 只有到达最边上的磁道时才能改变磁头移动方向（以上图为例，需要移到200号才换方向）
	- 对每个位置磁道的响应频率不平均
		- 如90号需要间隔很久，184号只需一会儿

- LOOK调度算法
	- 如果在磁头移动方向上已经没有别的请求，就可以立即改变磁头移动方向（边移动边观察）
	- 解决缺点1
	- ![Pasted image 20251226100700](images/Pasted%20image%2020251226100700.png)
-  循环扫描算法（C-SCAN）
	- 只有磁头朝某个特定方向移动时才处理磁道访问请求，返回时直接快速移动至起始段而不处理任何请求
	- 解决缺点2
	- ![Pasted image 20251226100844](images/Pasted%20image%2020251226100844.png)
	- 缺点
		- 不用返回到0，18即可
		- 平均寻道时间更长

- C-LOOK调度算法
	- 中和了LOOK和C-SCAN
	- ![Pasted image 20251226101218](images/Pasted%20image%2020251226101218.png)
	- 优点
		- 相较于C-SCAN，无需移动到最外侧或最内侧才改变磁头方向

### 4. 磁盘的管理

- 磁盘初始化
	- 进行低级格式化（物理格式化），将磁盘各个磁道划分为扇区（出厂之前）
		- 扇区分为头、数据区域、尾三个部分
		- 头、尾
			- 管理扇区所需要的各种数据结构
				- 扇区校验码（奇偶校验、CRC循环冗余校验码）
	- 将磁盘分区，每个分区由若干柱面组成（C盘、D盘、E盘）
	- 进行逻辑格式化，创建文件系统。
		- 创建文件系统的根目录
		- 初始化存储空间管理所用的数据结构（位示图、空闲分区表）

- 引导块
	- 计算机开机的初始化工作通过执行初始化程序（自举程序）完成
	- ROM（只读存储器）
		- 初始化程序放在ROM
			- 假如全部放在ROM，需要更新就很不方便
			- 解决方案
				- 只存放很小的自举装入程序
				- 完成的自举程序放在磁盘的启动块（引导块/启动分区）上
				- 启动块位于磁盘的固定位置
				- 开机时计算机运行自举装入程序找到引导块将完整版读入内存完成初始化
		- 数据在出厂时就写入了，并且之后不能再修改
		- ROM在出厂时就集成在主板上的 
	- 拥有启动分区的磁盘为启动磁盘（系统磁盘）
- 坏块的管理
	- 属于硬件故障，操作系统无法修复
		- 只能将坏块标记出来以免使用
	- 对简单的磁盘
		- 在*逻辑格式化时*对整个磁盘进行坏块检查标注坏扇区（例如在FAT上注明）
		- 坏块对操作系统不同透明
	- 对复杂磁盘
		- 磁盘控制器（磁盘设备内部的一个硬件部件）会维护一个*坏块链表*
		- 磁盘出厂前进行*低级格式化*时将坏块链进行初始化
		- 会保留一些“*备用扇区*”，用于替换坏块，这种方案称为扇区备用
		- 坏块对操作系统透明

### 5. 固态硬盘SSD

- 原理
	- 基于闪存技术Flash Memory，属于电可擦除ROM，即EEPROM

- 组成
	- 闪存翻译层
		- 负责翻译逻辑块号，找到对应页（Page）
	- 存储介质
		- 多个闪存芯片（Flash Chip）
		- 每个芯片包含多个块（block）
		- 每个块包含多个页（page）

- 读写性能特性
	- 以页（page）为单位读/写
		- 类似磁盘的扇区
		- 系统送来的块地址定位到页，而不是块
	- 以块（block）为单位擦除
		- 擦干净的块每页都可以写一次，读无限次
	- 支持随机访问，系统给定一个逻辑地址，闪存翻译层可通过电路迅速定位对应的物理地址
	- 读快，写慢
		- 要写的页如果有数据则不能写入，需要将块内的其他页全部复制到一个新的块中，再写入新的页
	- 结构
		- ![Pasted image 20251226143349](images/Pasted%20image%2020251226143349.png)
- 与机械硬盘相比
	- ![Pasted image 20251226142335](images/Pasted%20image%2020251226142335.png)
	- SSD读写速度快，随机访问性能高，用电路控制访问位置
		- 机械硬盘通过移动磁臂旋转磁盘控制访问位置，有寻道时间和旋转延迟
	- SSD安静无噪音、耐摔抗震、能耗低、造价贵
	- SSD的一个块被擦除次数过多（重复写同一个块）可能会坏
		- 机械硬盘的扇区不会因为写的次数太多而坏掉

- 磨损均衡技术
	- 思想
		- 将“擦除”平均分布再各个块上，提升使用寿命
	- 动态磨损均衡
		- 写入数据时，优先选择累计擦除次数少的新闪存块
	- 静态磨损均衡
		- SSD监测并自动进行数据分配、迁移
		- 让老旧的闪存块承担以读为主的储存任务
		- 新闪存块承担更多的写任务
	- 举例
		- ![Pasted image 20251226143549](images/Pasted%20image%2020251226143549.png)
