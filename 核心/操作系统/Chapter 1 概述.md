## Part 1 概念、功能和目标
- 目标：方便性、有效性、可扩充性、开放性
	- 方便性：高级语言
	- 有效性：系统吞吐量
	- 可扩充性：模块化结构
	- 开放性：国际标准
### 概念
- 概念：
	1. *控制和管理*整个计算机系统的*硬件和软件*资源
	2. 合理地组织调度计算机工作和资源的分配，以*提供给用户和其他软件方便的接口和环境*。
	3. 是计算机系统中最基本的*系统软件*。
### 作用
1. 系统资源管理者
	- 功能：
		- 处理机管理：软件运行需要cpu处理
		- 存储器管理：打开软件放入内存
		- 文件管理：软件在文件管理器中
		- 设备管理：使用视频摄像头涉及设备管理
	- 目标：安全、高效
2. 提供接口
	- GUI：图形化用户接口（Graphical User Interface）
	- 命令接口
		- 联机命令接口（交互式命令接口）：命令提示符cmd，一条一条来
		- 脱机命令接口（批处理命令接口）：C盘中的\*.bat文件，一次性提出一堆的请求
	- 程序接口（给软件或者程序员使用）：例如C语言中的库
3. 实现了对硬件机器的拓展

### 特征
- 四个基本特征
	- 最*基本*的两个特征，二者互为存在条件：并发、共享
	- *并发*：两个或多个事件在*同一时间间隔*内发生。宏观上是同时发生，微观上交替发生。
		- 并行：两个或多个事件在同一时刻同时发生
		- 单核CPU同一时刻只能执行一个程序，各个程序只能并发地执行。
		- 多核CPU同一时刻可以同时执行多个程序，多个程序可以并行地执行，但是单独一个核还是并发。
	- *共享*：即资源共享，系统中的资源可供内存中多个*并发执行的进程*共同使用
		- 互斥共享
			- 一个时间段只允许一个进程访问
		- 同时共享
			- 一个时间段多个进程“同时”对它们进行访问（这个同时是宏观上的，实际上是交替进行）
	- *虚拟*：把一个物理上的实体变为若干个逻辑上的对应物。物理实体是实际存在的，逻辑上的对应物是用户感受到的。
		- 空分复用技术
			- 虚拟存储器
		- 时分复用技术：
			- 虚拟处理器：单核cpu可以同时运行多个软件（将大时间段分成了很小的时间片）。
			- 微观上处理机在各个微小的时间段内交替为各个进程服务，宏观上有多个cpu的感觉
	- *异步*：在多道程序环境下，允许多个程序并发执行，但是资源有限，进程的执行不是一贯到底的，而是走走停停，以不可预知的速度向前推进。
		- A程序在A进程需要A资源，B程序在B进程需要A资源，那么B在轮到自己的时间片的时候会停（阻塞），等A把A资源让出来之后才会继续运行

## Part 2 发展和分类
- 解决了什么问题，各自的优缺点
- 提高cpu使用占比
### 1. 手工操作阶段√
- 输入输出慢：纸带机纸带手工装/取，从纸带机读/写
- 计算快
- 用户独占全机、人机速度矛盾导致资源利用率低。![[Pasted image 20250925213650.png]]
### 2. 批处理阶段
#### 单道批处理系统
- 引入脱机输入/输出技术（用外围机+磁带完成），由*监督程序*（操作系统雏形）负责控制作业的输入、输出
- 多个程序员可以将程序放入外围机，外围机将程序存到磁带里，计算机从磁带输入，再输出到另一个磁带。![[Pasted image 20250925213544.png]]

#### 多道批处理系统
- 每次往内存中读入多道程序，操作系统应运而生用于支持多道程序并发运行。![[Pasted image 20250925213445.png]]
- 优点：
	- 多道程序并发执行，共享计算机资源。*资源利用率*大幅提升，*系统吞吐量*增大。
- 缺点：
	- 用户响应时间长，*没有人机交互*功能
	- 无法调试程序/无法在程序过程中输入一些参数

### 3. 分时操作系统
- 计算机以*时间片*为单位轮流为各个用户/作业服务，各个用户可通过终端与计算机进行交互
- 优点：
	- 用户请求可以被即时响应，解决了*人机交互问题*。允许多个用户同时使用一台计算机，并且用户对计算机的操作相互独立。
- 缺点：
	- *不能优先处理一些紧急任务*。操作系统对各个用户/作业都是完全公平的，循环的为每个用户/作业服务一个时间片，不区分任务的紧急性。

### 4. 实时操作系统
- 优点：
	- 能够*优先响应*一些紧急任务，某些紧急任务不需要时间片排队。
- 在实时操作系统的控制下，计算机系统接收到外部信号后及时处理，并且要在严格的时限内处理完事件。
	- 特点：及时性、可靠性
- 分类
	- 硬实时系统：必须在绝对严格的规定时间内完成处理（导弹控制系统、自动驾驶系统）
	- 软实时系统：能接收偶尔违反时间规定（订票系统）

### 5. 其他的操作系统
- 网络操作系统：实现网络中各种资源的共享（文件共享）和各台计算机之间的通信
- 分布式操作系统：分布性、并行性，任何工作都可以分布在这些计算机上，由它们并行、协同完成这个任务。
- 个人计算机操作系统：Windows XP、MacOS

## Part 3 运行机制
- 内核（kernel）：操作系统最核心、也是最接近硬件的部分，可以说最简单的操作系统只要有内核就够了（Docker-->仅需Linux内核），系统管理者
- *程序运行的过程*
	- 其实就是CPU执行一条条机器指令的过程
### 1. 两种程序
- 内核程序
	- 多个内核程序组成了操作系统内核
- 应用程序
	- 普通程序员编写的程序
### 2. 两种指令
- 在CPU设计和生产的时候就划分了特权指令和非特权指令，所以CPU执行一条指令之前就能判断出其类型
- 特权指令
	- 操作系统内核让CPU执行的指令就是“特权指令”，只允许操作系统内核使用
- 非特权指令
	- 应用程序只能使用非特权指令，如加法指令、减法指令
### 3. 两种处理器状态
- 核心态/内核态/管态
	- 说明此时运行的是内核程序，可以执行特权指令
- 用户态/目态
	- 说明此时运行的是应用程序，只能执行非特权指令
- CPU中有一个寄存器叫程序状态字寄存器（PSW，Program Status Word），其中有一个二进制位，1表示“内核态”，0表示用户态（不一定）
- 状态
	1. 刚开机时，CPU为“*内核态*”，操作系统内核程序在CPU运行
	2. 开机后*用户启动*应用程序，内核程序让出CPU给应用程序，此时是“用户态”
	3. 假如此时应用程序中植入了一条特权指令，而CPU处于“用户态”，该*非法事件*引发中断信号
	4. CPU检测到*中断信号*之后变为“核心态”并且停止当前应用程序，从而运行处理中断信号的内核程序
	5. 处理完了之后再把CPU使用权交给*应用程序*
- 状态切换
	- 内核态-->用户态：执行一条特权指令——修改PSW的标志位为“用户态”，主动让出CPU使用权
	- 用户态-->内核态：由“中断”引发，硬件自动完成状态切换过程，操作系统强制夺回CPU使用权（自动完成）

## Part 4 中断和异常
### 1. 作用
- “中断”是让操作系统内核夺回CPU使用权的*唯一*途径
### 2. 类型
- 内中断（异常、例外）
	- 与当前执行的指令*有关*，中断信号来源于CPU*内部*
	- 陷阱、陷入（trap）：应用程序故意引发
	- 故障（fault）：可能被内核程序修复，修复后CPU还给应用程序
	- 终止（abort）：致命错误引起，无法修复，直接终止应用程序
	- 例子：
		- 在正在运行的应用程序中植入一条特权指令的方式就是内中断
		- 应用程序请想求操作系统内核服务，执行一条特殊的指令（不是特权指令）——陷入指令，引发内部中断信号
- 外中断（中断）
	- 与当前执行的指令*无关*，中断信号来源于CPU*外部*
	- 时钟中断；I/O中断请求
	- 例子
		- 时钟中断：时钟部件每隔一个时间片（如50ms）給CPU发送一个时钟中断信号（实现并发），CPU接收到中断信号之后运行内核程序，内核程序将CPU让给另一个应用程序使用
		- I/O中断：输入/输出设备发来的中断信号，比如说打印机打印完了会发送一个中断信号告诉CPU，让内核程序及进行处理
### 3. 中断机制的基本原理
- 不同的中断信号由不同的中断处理程序处理。
- CPU检测到中断信号后，会根据其类型去查询“*中断向量表*”从而运行对应的中断处理程序
- 运行在“*内核态*”

## Part 4 系统调用
### 1. 什么是系统调用？
- 解释：
	- 操作系统提供给*应用程序*（程序员）使用的接口（比库函数更底层），可以理解为 可供应用程序调用的特殊函数
- 应用程序可以通过*系统调用*来请求获得操作系统内核的服务。

- 作用：用户进程想要使用*共享资源*，只能通过系统调用向操作系统内核提出请求，内核可以进行协调处理。

### 2. 系统调用与库函数的区别
- 系统调用是比库函数更底层的一个接口
- 高级语言有时候会将系统调用封装成库函数来隐藏系统调用的一些细节，是编程更方便。![[Pasted image 20250927122913.png|400]]

### 3. 系统调用过程
- 陷入指令/trap指令/访管指令
![[Pasted image 20250927163544.png]]

1. 传递系统调用参数
2. 执行陷入指令（用户态）
3. 执行内核程序（核心态）
4. 返回应用程序
### 4. 什么功能需要用系统调用？
- 设备管理：完成设备的 请求/释放/启动
- 文件控制：完成文件的 读/写/创建/删除 
- 进程控制：完成进程的 创建/撤销/阻塞/唤醒 
- 进程通信：完成进程之间的 消息传递/信号传递 
- 内存管理：完成内存的 分配/回收

- 和共享资源有关的操作（存储分配、I/O操作、文件管理）都必须通过系统调用的方式向操作系统内核提出服务请求。保证系统的稳定性和安全性。

## Part 5 体系结构
### 大内核和微内核
- 也就是操作系统的内核该如何设计？
![[Pasted image 20250927164031.png]]

- 操作系统内核
	- 时钟管理：实现计时功能（硬件关联紧密）
	- 中断处理：实现中断机制（硬件关联紧密）
	- 原语（硬件关联紧密）
		- 一种特殊的程序
		- 处于操作系统最底层，最接近硬件的部分
		- 这种程序的运行具有原子性——运行只能一气呵成，不可中断
		- 运行时间较短、调用频繁
	- 对系统资源进行管理的功能（更多的是对数据结构的操作）
		- 进程管理
		- 存储器管理
		- 设备管理

![[Pasted image 20250927164516.png]]

- 大内核与微内核体系结构比较![[Pasted image 20250927164735.png]]
- 频繁的转换CPU状态会降低系统性能
- 大内核：Linux、Unix
	- 优点：高性能（内核是模块化的，调用更快）
	- 缺点：内核代码庞大、结构混乱，难以维护
- 微内核：Windows NT
	- 优点：内核功能少，结构清晰，方便维护（某一个功能出错不会影响到整个系统）
	- 缺点：需要频繁的核心态和用户态之间切换，性能低（使用进程等功能需要通过内核进行*消息传递*，性能差）

### 其他
- 分层结构
	- 内核分为多层，每层只可以调用低一层的接口，最底层是硬件，最高层是用户接口
	- 优点：
		- 便于调试和验证
		- 易扩充和易维护
	- 缺点：
		- 只可以调用相邻低层，难以定义各层边界
		- 效率低，不可以跨层，系统调用执行时间长
- 模块化
	- 将内核划分为多个模块，各模块之间相互协作
	- 内核=主模块+可加载模块
		- 主模块：负责核心功能，如进程调度、内存管理
		- 可加载模块：可以动态加载到内核，不用重新编译整个内核，如驱动
	- 优点：
		- 模块间逻辑清晰，易于维护，可以多模块开发
		- 支持动态加载新的内核模块，增强OS适应性
		- 任何模块都可以直接调用其他模块，无需消息传递进行通信，效率高
	- 缺点：
		- 模块的定义不一定合理实用
		- 模块之间相互依赖，难以调试
- 外核（exokernel）
	- 内核负责进程调度、进程通信，外核负责为用户进程分配*未经抽象的硬件资源*（不离散的地址空间）并且保证资源使用安全
	- 优点：
		- 可以直接给用户进程分配“不虚拟，不抽象”的硬件资源，使用户进程更灵活的使用硬件资源
		- 减少了虚拟硬件资源的“映射层”，提升效率
	- 缺点：
		- 降低了系统一致性
		- 使系统变得更复杂

## Part 6 操作系统引导（boot）
- 开机的时候如何让操作系统运行起来？

- 磁盘的开头位置会留出一片区域（主引导记录MBR，Master Boot Record）包含磁盘引导程序和分区表（一个数据结构，说明了后面每个分区分别*占多大的空间*和*地址范围*）
- C盘（系统盘）： 安装了操作系统
	- 引导记录PBR（Partition Boot Record）：负责找到“启动管理器”（在根目录）
	- 根目录和其他
![[Pasted image 20250927172852.png]]

- boot的过程
	1. CPU从一个特定的主存地址（ROM中）开始，取指令，执行ROM中的引导程序（先进行硬件自检，再开机）
	2. 将MBR读入内存（RAM），执行磁盘引导程序，扫描分区表
	3. 从C盘读入PBR，执行其中的程序
	4. 从根目录下找到完成的操作系统初始化程序（启动管理器）并执行，完成开机

## Part 7 虚拟机
- 使用虚拟化技术将一台物理机器虚拟化为多台虚拟机器，每个虚拟机器可以独立运行一个操作系统
- 同义语：虚拟机管理程序/虚拟机监控程序/Virtual Machine Monitor/Hypervisor

![[Pasted image 20250927204221.png]]
- 第一类虚拟机（type1）
	- 能直接运行在硬件之上，可以直接控制和分配物理资源
	- VMM在原本的硬盘上分配存储空间，类似外核的分配方式，分配未经抽象的物理硬件
	- 性能更好
	- 可支持的虚拟机数量更多
	- 可迁移性差
	- 运行模式：第一类VMM运行在最高特权级（Ring 0），可以执行最高特权的指令

![[Pasted image 20250927204234.png]]

- 第二类VMM（type2）
	- 运行在Host OS之上，依赖Host OS分配物理资源
	- 拥有自己的虚拟磁盘，实际上是Host OS文件系统中的一个大文件，分配到的内存使虚拟内存
	- 性能更差，需要Host OS作为中介
	- 可支持的虚拟机更少
	- 迁移性更好
	- 运行模式：部分运行在用户态，部分在内核态。发出的系统调用会被VMM截获，并且转化为VMM对Host OS的调用
